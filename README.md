# دَرِت ربات (Daret.ir Telegram Bot)

ربات تلگرام اینلاین برای وب‌سایت [دَرِت (daret.ir)](https://daret.ir/) توسعه داده شده با Python 3.14 و [aiogram v3](https://docs.aiogram.dev/).

این ربات به کاربران اجازه می‌دهد در هر چت یا گروهی لیست درهای وب‌سایت دَرِت را به صورت اینلاین جستجو کرده، پیش‌نمایش تصویر و توضیحات هر در را ببینند، و پیام نهایی را ارسال کنند. همچنین دارای گزینه انتخاب در شانسی به صورت زنده است.

> ⚠️ **سلب مسئولیت و کپی‌رایت (Disclaimer & Copyright):**  
> این ربات یک پروژه مستقل است و پروژه رسمی وب‌سایت [daret.ir](https://daret.ir/) نمی‌باشد. این بات بر پایه و با الهام از وب‌سایت دَرِت ساخته شده است و تمامی حقوق مادی، معنوی و کپی‌رایت محتوا و آثار متعلق به سازندگان دَرِت ([haashemi.dev](https://haashemi.dev/)) محفوظ است.

> 🌙 **درباره توسعه (Vibe Coding):**  
> این پروژه به صورت vibe-coded و صرفاً برای تفریح و سرگرمی در دل نیمه‌شب توسعه پیدا کرده است! پلن‌ها توسط **GPT 6.1 Sol** نوشته شده و پیاده‌سازی با **Gemini 3.8 Flash** انجام گرفته است. با تشکر ویژه از **GitHub Copilot**.

## ویژگی‌ها

1. **حالت اینلاین (Inline Mode):** پیشنهاد درها با تایپ کردن `@botusername` در هر گفتگو.
2. **تصویر در لیست پیشنهادات (Thumbnail in Suggestions):** هر در در منوی اینلاین همراه با عکس بندانگشتی اختصاصی خود نمایش داده می‌شود (`/doors/{slug}.jpg`).
3. **ارسال پیام با پیش‌نمایش لینک (Link Preview):** پیام ارسالی به صورت متن فرمت‌شده همراه با پیش‌نمایش غنی لینک وب‌سایت است.
4. **جستجوی هوشمند درها:** قابلیت جستجو در عنوان، توضیحات و شناسه درها با نرمال‌سازی حروف فارسی/عربی (ی/ي، ک/ك، نیم‌فاصله، اعراب و کشیده).
5. **در شانسی (Random Door):**
   - در حالت اینلاین گزینه «🎲 یه در شانسی!» نمایش داده می‌شود.
   - هنگام انتخاب، ابتدا پیام موقت (`در حال پیدا کردن دَرِت...`) با دکمه ارسال می‌شود.
   - سپس از طریق فیدبک تلگرام (`chosen_inline_result`)، متن پیام به صورت زنده با یک در تصادفی و پیش‌نمایش لینک آن جایگزین می‌گردد. همچنین دکمه شیشه‌ای فال‌بک برای حالتی که فیدبک غیرفعال باشد قرار داده شده است.
6. **فرمت پیام نهایی:**
   ```text
   **در باجه تلفن‌!**
   باجه‌ی قرمز با کلی شیشه‌ی کوچیک. تلفنش سکه می‌خوره و دیگه هیچ‌کس سکه نداره.
   حالا برو [درتو](https://daret.ir/door/phone-booth) بذار.
   ```
6. **کشینگ هوشمند بر اساس تقاضا (Demand-Driven Stale Cache):**
   - به جای رفرش اجباری و بی‌دلیل در پس‌زمینه، با رسیدن هر درخواست اینلاین، تازگی کش بررسی می‌شود (`DOORS_CACHE_TTL_SECONDS`).
   - اگر کش منقضی شده باشد، تسک مشترک نوسازی در پس‌زمینه شروع به کار می‌کند و ربات حداکثر تا سقف زمانی مشخص‌شده (`DOORS_CACHE_REFRESH_MAX_WAIT_SECONDS` با مقدار پیش‌فرض ۵ ثانیه) منتظر دریافت اطلاعات تازه می‌ماند.
   - در صورت طولانی شدن یا بروز خطا در فرآیند نوسازی، ربات بلافاصله اطلاعات کش قبلی (Stale) را تحویل می‌دهد تا کاربر معطل نشود؛ همچنین رسیدن به سقف زمانی باعث لغو تسک نوسازی نمی‌شود و رفرش تا پایان در پس‌زمینه ادامه می‌یابد.
7. **مدیریت متغیرهای محیطی با `python-decouple`:**
   - خواندن توکن و تنظیمات از فایل `.env`.

## پیش‌نیازها و نصب با uv

این پروژه با [uv](https://docs.astral.sh/uv/) مدیریت می‌شود.

### ۱. همگام‌سازی و نصب وابستگی‌ها

```bash
uv sync
```

این دستور پکیج‌های پروژه (شامل `aiogram`, `httpx`, `python-decouple`, `beautifulsoup4`, `pytest`) را درون محیط مجازی پروژه نصب و همگام می‌کند.

### ۲. تنظیم فایل `.env`

فایل `.env.example` را به عنوان الگو بررسی کرده یا یک فایل `.env` ایجاد کنید:

```env
# توکن دریافتی از @BotFather
TELEGRAM_API_TOKEN=your_bot_token_here

# مدت زمان کش کاتالوگ درها در حافظه به ثانیه (پیش‌فرض: ۳۰۰ ثانیه = ۵ دقیقه)
DOORS_CACHE_TTL_SECONDS=300

# حداکثر زمان انتظار برای نوسازی کش در صورت انقضا پیش از استفاده از کش قدیمی (ثانیه)
DOORS_CACHE_REFRESH_MAX_WAIT_SECONDS=5.0

# آدرس وب‌سایت دَرِت
DARET_BASE_URL=https://daret.ir

# تایم‌اوت درخواست‌های HTTP به ثانیه
HTTP_TIMEOUT_SECONDS=15.0

# حداکثر تعداد درخواست‌های همزمان هنگام اسکرپ جزئیات درها
SCRAPE_CONCURRENCY=5

# مدت زمان کش سمت کلاینت تلگرام برای پاسخ‌های اینلاین (ثانیه)
INLINE_CACHE_TTL_SECONDS=10
```

## تنظیمات در BotFather (الزامی برای حالت اینلاین)

برای فعال‌سازی و عملکرد صحیح اینلاین و در شانسی:

1. به ربات [@BotFather](https://t.me/botfather) در تلگرام بروید.
2. دستور `/setinline` را ارسال کرده و ربات خود را انتخاب کنید. یک متن راهنما وارد کنید (مثلاً: `درِت رو انتخاب کن...`).
3. دستور `/setinlinefeedback` را ارسال کنید، ربات خود را انتخاب کنید و مقدار را روی **100% (Enabled)** قرار دهید. این تنظیم برای دریافت رویداد `chosen_inline_result` و جایگزینی خودکار در شانسی ضروری است.

## اجرای ربات

پس از قرار دادن توکن معتبر در فایل `.env`:

```bash
uv run daretirbot
```

یا از طریق ماژول پایتون:

```bash
uv run python -m daretirbot
```

## استقرار با داکر (Docker)

پروژه دارای یک `Dockerfile` چندمرحله‌ای (Multi-stage) منطبق با بهترین الگوهای رسمی `uv` است:
- **مرحله ساخت (Builder):** استفاده از ایمیج رسمی `python:3.14-slim` و باینری پین‌شده `uv`، کش لایه‌ای برای وابستگی‌های قفل‌شده (`uv.lock`)، و نصب پروژه در حالت غیرقابل ویرایش (`--no-editable`).
- **مرحله اجرا (Runtime):** فقط محیط مجازی خروجی به یک ایمیج تر و تمیز منتقل می‌شود؛ اجرای ربات تحت کاربر غیرریشه (`appuser:appgroup` با شناسه 10001) و بدون ابزارهای بیلد انجام می‌پذیرد.

### ساخت ایمیج داکر به صورت لوکال

```bash
docker build -t daretirbot .
```

### اجرای کانتینر

با توجه به اینکه ربات از روش Long-polling تلگرام استفاده می‌کند، **تنها یک کانتینر فعال** باید همزمان در حال اجرا باشد و به شبکه خروجی اینترنت دسترسی داشته باشد:

```bash
docker run -d \
  --name daretirbot \
  --restart unless-stopped \
  --env-file .env \
  daretirbot
```

مشاهده لاگ‌ها:

```bash
docker logs -f daretirbot
```

### دریافت ایمیج از رجیستری گیت‌هاب (GHCR)

ایمیج‌های رسمی پس از هر انتشار به صورت خودکار در GitHub Container Registry منتشر می‌شوند:

```bash
docker pull ghcr.io/alirezaja1384/daretirbot:latest
docker run -d --name daretirbot --restart unless-stopped --env-file .env ghcr.io/alirezaja1384/daretirbot:latest
```

## پایپ‌لاین CI/CD و نسخه‌گذاری معنایی (Semantic Release)

این پروژه مجهز به گردش‌کارهای خودکار گیت‌هاب اکشنز (GitHub Actions) است:

1. **اعتبارسنجی پول‌ریکوئست‌ها (`.github/workflows/ci.yaml`):**
   - نصب خودکار ابزار `uv` و کش وابستگی‌ها.
   - اجرای تمام تست‌های خودکار با `pytest`.
   - اعتبارسنجی بیلد پکیج توزیع پایتون (`uv build`).
   - بیلد آزمایشی ایمیج داکر به صورت لوکال و تست بررسی سلامت (Smoke test) با ایمپورت موفق ماژول در کانتینر.

2. **نسخه‌گذاری خودکار و انتشار ایمیج (`.github/workflows/release.yaml`):**
   - با پوش یا مرج شدن در برنچ `main` فعال می‌شود.
   - ابتدا مجدداً تست‌ها و بیلد اعتبارسنجی می‌شوند.
   - بر اساس ساختار **Conventional Commits**، تگ معنایی بعدی محاسبه و به گیت ارسال می‌شود:
     - کامیت‌های معمولی یا `fix:` -> ارتقای **Patch** (پیش‌فرض).
     - کامیت‌های `feat:` -> ارتقای **Minor**.
     - کامیت‌های دارای `BREAKING CHANGE:` یا `!` -> ارتقای **Major**.
     - با درج `#skip-release` می‌توان از صدور نسخه جدید صرف‌نظر کرد.
   - انتشار گیت‌هاب (GitHub Release) همراه با لیست تغییرات (Changelog) خودکار ثبت می‌شود.
   - ایمیج نهایی به همراه تگ‌های معنایی کامل (`x.y.z`، `x.y`، `x`، `latest` و `sha-*`) در رجیستری `ghcr.io` بیلد و پوش می‌گردد.
